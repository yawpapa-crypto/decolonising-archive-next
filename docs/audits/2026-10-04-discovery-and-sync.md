## Findings and strategy

1. **Current organic architecture.** Next.js 16.2.6 App Router, React 19, server metadata and React-cached KGO readers coexist with dynamic redesigned discovery, live provider APIs, a cached image pool, Supabase auth/RLS and public curatorial projections. Both `next.config.ts` and `next.config.mjs` exist: verify the effective configuration during the production build before evaluating redirects/cache headers.
2. **Critical failures.** P0 investigation: production audit 429s; public-record access filtering; client-only/floating record presentation; soft redirects for missing records; private service-worker caching; unsafe JSON-LD serialization of potentially untrusted strings. These are findings to validate and prioritise, not a security-clearance statement.
3. **Crawl/indexation.** Local XML is valid and has 4,514 unique URLs: 4,381 Explore URLs, 20 records and 113 other entries. This count is not the number indexed or the number of successful landing pages. Production sitemap and robots could not be read.
4. **Rendering.** `/records/l001` returns its subject H1, deterministic title, self canonical and JSON-LD in server HTML. The home and Explore response samples demonstrate that shared chrome does not guarantee substantive record content; the root sample has no H1. Dev response timings include compilation and are not production CWV measurements.
5. **URL architecture.** The museum catalogue ID `ARED-GH-00055` is absent from the KGO `/records/[id]` lookup: it redirects to root. Its legacy collection URL redirects into `/home-next/explore?record=…`, which is noindex. The previous request to bypass the old visual page is preserved; a public server document can later share the redesigned presentation without reinstating that old page.
6. **Canonicals.** `/home-next` canonicalises to root while declaring noindex/nofollow. Explore detail has no explicit canonical in the sampled document. KGO record canonical identity works for l001. Check inherited root canonicals for every page family, and keep tracking parameters outside canonical identity.
7. **Sitemap architecture.** `app/sitemap.ts` produces one sitemap including programmatic hubs. 4,514 entries are within one-sitemap size limits; splitting alone will not fix eligibility. Gate by public/substantive content first. Static/entity/hub lastmod uses request time, and missing record update dates use current time. Use meaningful persisted revisions or omit unknown dates.
8. **Robots policy.** Private/auth prefixes are disallowed for `*`. The crawler-specific GPTBot/ClaudeBot/Google-Extended groups have less complete private exclusions. Robots is a crawl directive, never access control. Review each specific group independently and check HTTP authentication first.
9. **AI crawler policy.** No explicit OAI-SearchBot group was found; it falls under the wildcard rules. GPTBot is explicitly permitted broadly. Search discovery and training are independent controls in [OpenAI's official crawler documentation](https://developers.openai.com/api/docs/bots). Recommend deliberate public search access and a separately recorded training decision; no policy was silently changed.
10. **Record SEO.** Preserve deterministic metadata and provenance. Reconcile catalogue and KGO identity/publication gates before adding more record URLs. Missing records should eventually return a meaningful 404/410 rather than a root redirect. This audit did not introduce a redirect.
11. **Book SEO.** The common schema chooses Book when the record type contains book, but type-correctness, ISBN, edition and publisher coverage need a real bibliographic sample. Designed card graphics must stay distinguishable from verified publisher covers.
12. **Article SEO.** Current schema maps journal/article text to ScholarlyArticle without a separate scholarly verification check. Review literal authors, DOI, journal and permitted abstract fields; do not infer scholarly authority from a generic article label.
13. **Collection SEO.** Ghana's old public collection route redirects to the redesigned collection, whose metadata declares noindex/follow and has no canonical/schema in the observed response. Add public authority-hub metadata only after deciding stable identity and visible curatorial scope. Private reading-list collections stay private.
14. **Profile SEO.** Owner profile is noindex. Public actor/person routes need field-level consent, factual name/entity identity and sufficient public collections. No private biography or saved history should appear through public projection.
15. **Image SEO.** l001 has no record image represented in the common record schema; observed image tags alone include shared chrome. `recordJsonLd` omits ImageObject. Audit source permissions, factual alt, dimensions, stable cached URLs, surrounding source/rights and record association. Floating decorative images are not substantive image landing pages.
16. **Structured data.** Existing Website, Organization, breadcrumbs, records, entities and item lists are worth retaining. Current `JsonLd` inserts raw JSON.stringify output into a script: escape `<` before using untrusted metadata. Creator is always Person; institutions/cultures must not become fictitious people. isPartOf currently points every record to the generic library rather than a verified collection relationship.
17. **Internal link graph.** Entity paths and record related links exist in code. The new modal also links directly to real sources. Crawlable public record/entity anchors must remain underneath interactive feeds. Capture actual link edges after production access is available; no complete graph degree count is asserted here.
18. **Orphan pages.** No production orphan count is available. Sitemap-only discovery is not evidence of contextual internal links. Candidate priority: the 20 KGO records and catalogue objects whose only ARED detail URL is an app query state. Full edge extraction remains pending.
19. **Faceted policy.** Keep ordinary query/search/sort states out of sitemaps. Individually index only justified substantive public hubs. The 4,381 generated Explore entries are disproportionate to 20 KGO record entries; review their actual record coverage and remove empty/thin combinations from discovery before content growth.
20. **Infinite-scroll crawlability.** Explore/For You depend on client API continuation. Shared public record identities, contextual links and eligible sitemaps can provide a crawler path without exposing personalised feed APIs. Do not make a crawler simulate endless scrolling.
21. **Core Web Vitals.** Analytics, Speed Insights and a WebVitalsReporter already exist. No production LCP/INP/CLS/TTFB baseline was available. Capture field data for home, record, collection, Explore and public profile; use local traces only for debugging, not as a CWV success claim.
22. **Search Console.** Property ownership, indexing, queries, image performance, canonical conflicts and generative reporting are unverified. [Google's current guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) describes the Generative AI performance report. Do not invent dashboard metrics or claim a property is configured from a missing source-code token alone.
23. **Bing.** No Bing verification or Webmaster access was found in this audit. Confirm property ownership and submitted sitemap from the dashboard before judging coverage.
24. **IndexNow decision.** No implementation found. Recommend P2, after public URL/access and update-date correctness. Publish only newly created/materially changed/deleted eligible public URLs through a bounded retry queue, with a verified key file. [Microsoft's guide](https://www.bing.com/indexnow/getstarted) states notification does not guarantee crawling or indexing. Do not submit private deletions or historical bulk unchanged URLs.

No format is declared validated merely because its route exists.

## Peer benchmark and next implementation order

The verified Cleveland primary record separates identity, accession, object metadata, institution, image and public licence clearly. ARED should add its own verified relational context while keeping that primary record authoritative. Europeana's existing ARED integration retains institution/data-provider/aggregator/rights separately; extend the same provenance clarity to indexable record documents rather than inferring object geography from provider country. This is a targeted structural comparison, not an exhaustive competitor/performance crawl.

P0: establish production crawler access; unify access/publication gates; address private cache and serialization risks; choose one durable public record identity; test missing/restricted IDs across HTML and APIs.

P1: meaningful public SSR record text and image/rights metadata; validate type-specific schema, titles, canonicals and social images; truthful sitemap dates/eligibility; contextual internal links; actual performance traces.

P2: substantive entity/collection authority hubs, first-party dashboard setup, citation format QA, measured orphan repair, bounded IndexNow only after correctness.

P3: evidence-led editorial work, public RSS if worthwhile, approved social distribution and institutional citation/link outreach. No social messages were sent.

The brief's audit-first boundary is honoured. A production-access and content-identity decision is required before a safe site-wide discovery implementation; this report does not claim “SEO optimised.”
