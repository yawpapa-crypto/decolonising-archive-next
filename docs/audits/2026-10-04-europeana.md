# Europeana integration audit (before changes)

The image pool lives in `lib/home/discover.ts`: hourly cached `getHomeCollage()` tiles are converted to `DiscoverItem`, then searched locally. `lib/home/for-you.ts` combines that pool with live Commons and reading providers; later pages additionally use Met/Library of Congress. Native recommendations have another bounded public-provider candidate cache.

`lib/home/home-collage.ts` already has a server-only Europeana call, but only for a fixed homepage query and only when EUROPEANA_API_KEY exists. It does not query Europeana with the visitor's search. It drops creator/date/description/institution/country/subjects and merges the aggregator into the institution label; its licence fallback incorrectly implies an open licence. Both supplied unversioned endpoint and documented v2 alias answered the initial live Ghana probe.

Adapters return DiscoverItem and use bounded/time-limited cached server fetches. Partial sources catch errors to empty arrays. Images use cachedImageSrc and the existing strict-host archive proxy; broken client images already become typographic fallback tiles. Existing shared dedupe uses ID, truncated title/subtitle, image hash and ISBN; title-only dedupe is too aggressive for distinct archival photographs. Collage dedupe also merges identical titles regardless of institution/identifier.

Extend rather than replace: one Europeana adapter with defensive normalisation, source=Europeana and separate provenance/rights; reuse it for homepage and query-led shared pool, then bounded recommendation candidates. Use preview URLs and existing cache/proxy, no full-record-per-tile fetch, art-theme restriction or query geography injection. Preserve grid/cards/filters; only add metadata to the existing detail panel. Add archival-aware identity keys and isolated adapter tests plus live application searches for the ten requested terms. API key stays in ignored server environment configuration.

## Implementation and verification

1. **Files changed in this integration:** `lib/home/europeana.ts`, `lib/home/europeana-normalize.ts`, `lib/home/discover-shared.ts`, `lib/home/discover.ts`, `lib/home/home-collage.ts`, `lib/recommendations/server.ts`, `app/api/recommendations/events/route.ts`, `app/home-next/for-you/Detail.tsx`, `app/home-next/for-you/page.tsx`, `app/home-next/explore/page.tsx`, `tests/europeana.test.mjs`, `tests/europeana-live.mjs`, this audit, ignored `.env.local` and `.env.local.example`, and verification artifacts under `artifacts/europeana/`. Other pre-existing checkout changes were retained.
2. **Provider:** server-only `lib/home/europeana.ts`, backed by the testable adapter/normalizer. Uses the requested endpoint and supplied key via the server-only `X-Api-Key` header, as preferred by current Europeana authentication documentation; key is absent from client objects and URLs. Deployment needs the same server environment variable.
3. **Normalization:** existing `DiscoverItem`, retaining actual title, creator, date, description, preview, original resource, record URLs, provider, institution, country, rights, ID and subjects when supplied. No invented metadata. Provider country is not labelled as object geography. Rejects missing/invalid previews, known placeholders, opt-out records and records excluded by the existing cultural-image policy.
4. **Shared pool:** query-led `imageStream` interleaves Europeana with the cached existing pool; the existing Explore/For You multi-provider pipeline and recommendation candidate cache reuse it. Decorative homepage Europeana candidates require explicit open rights. User queries are literal, without a geography suffix or art-theme restriction. Existing cards, grid, filters and routes remain. Hourly cached API requests, bounded rows, six-second timeout and the existing preview-image proxy are reused.
5. **Deduplication:** existing shared keys now compare canonical record URLs and original/preview media, decode Europeana thumbnail target URLs and normalize Commons thumbnail URLs. Distinct archival objects with identical titles survive; book/article title and ISBN handling remains. Pagination retains separate Europeana IDs.
6. **Rights/provenance:** existing detail panel exposes Europeana separately from holding/data provider and aggregator provider, actual rights links, provider country, preview distinction and original institution record. Unknown rights remain unknown; only recognized fully open licences qualify as open access.
7. **Tests:** 16 unit tests passed (Europeana, cached images and existing recommendation engine), including malformed responses, zero results, rate limits, timeouts, canonical deduplication, distinct same-title objects and literal query/pagination. TypeScript and focused ESLint passed. Production build passed for Explore, For You, discover, explore and home-collage routes. Live application API searches exercised all ten requested terms, with existing providers responding throughout; nine searches returned four Europeana objects each. Each nonempty search had a sampled cached preview return HTTP 200/image JPEG. `graphic design Ghana` returned no Europeana candidates while 24 other results remained. Live discover image pool and Accra second-page checks passed (four distinct Europeana IDs per page). Browser inspection confirmed mixed results, loaded archival previews and provenance in the existing record panel. Raw counts are saved in `artifacts/europeana/live-results.json`; screenshots are `shared-pool.png` and `provenance.png`.
8. **Limitations:** upstream metadata, relevance and image availability vary. The adapter preserves literal search intent rather than broadening zero-result queries. Preview validity is structurally checked and sampled live, not guaranteed permanently for every upstream file. Cross-provider duplicates without shared canonical identities or media can remain; identical titles alone are deliberately insufficient. Full-site build and authenticated save/account journeys were not part of this integration verification; the affected routes built successfully. No remote deployment was performed.
